The Internet of Cognition
Agents coordinating to take on bigger work

Mycelium is part of a project called the Internet of Cognition. You'll probably hear about it a lot over the course of Shift.Forward.

The Internet of Cognition is about agentic coordination: agents working together to take on tasks and projects bigger than the ones they take on today.

Scaling agents out, to longer tasks and bigger problems.
Agents coordinating without a central coordinator

Back to what we're focused on: scaling agents out across longer-horizon tasks, and to bigger problems.

One thing we're experimenting with a lot is agents coordinating without a central coordinator. To explain what that means, let's look at how agent systems usually work.

One agent

An orchestrator

One point of failure

Coworkers

Now: one agent doing tasks one at a time. This is what we were all doing six months to a year ago. It's great because the agent keeps all the context of the task. But it's limited by its context window (the ring fills, then compacts) and in what it can do in parallel.

Press: so we moved to an orchestrator, which is what you see in Claude Code, Codex and Cursor. The agent you talk to hands work out to subagents. Each gets a subset of tools (maybe it can't edit files, maybe it can't browse), does one piece, and dies. That's good for things like broad research. But a lot rides on the summary each subagent sends back, and the orchestrator has to take all of them in and make sense of them.

Press: and it's a central point of failure. Prompt the main agent wrong, and the mistake runs all the way down the chain. To be clear, this might be the right pattern for your use case. Use the right tool for the job.

Press: what Mycelium is built around: agents as coworkers. Each is responsible for something (a part of the codebase, the release process, QA), keeps its context and its specialty, and talks to the others directly. They can break into subteams and work together.

What if agents kept their context?
Best practice says clear it. For this experiment, we don't.

General best practice is to clear an agent's context often, because of how next-token prediction works. For this experiment, let's pretend that rule doesn't exist.

An agent that owns one job learns its behaviors and edge cases. The release agent doesn't relearn the release pipeline; the QA agent doesn't relearn QA. That carries through compaction. So let's lean into that compounding context and see how powerful a system we can build. That's the idea behind Mycelium.

What gets hard

Talking

Agents have no standard way to talk to each other and coordinate.

Shared context

Stay specialists, without losing sight of what everyone else is doing.

Identity

What each one is responsible for, and how it's expected to act.

This is a new way of working, so first: what's hard about it.

Talking. There are few tools for agents to talk to each other. Anthropic has added some message passing, but agents don't do it unless you prompt them to. And I don't mean subagents; I mean agent to agent, across tabs. (A2A exists, but that's another thing.)

Shared context. We want specialists who still know what everyone else is doing. Like a daily stand-up with your coworkers, they need the same cadence of staying aligned.

Identity. Coding agents today are generalists: they work broadly across a codebase. For this experiment we lean into specialization: you're the QA agent, you're the release agent, you're the designer. And we see how far they get that way.

Tasks.

Goals written down as something every agent can see and work on.

A way to talk.

A CLI: private thinking, public messages, quiet until asked.

Memory.

Recall what the room already discussed and decided.

Tasks. Agents need a way to coordinate on goals, and the best way is to make the goals a real artifact they all work on. It's not unlike spec-driven development, except the agents own the spec, so they can organize themselves.

Press, a way to talk. When OpenClaw was popular, we put a bunch of OpenClaw agents in a chat room. They fell into what we called AI theater: endless chatting, yes-men to each other. Every message landed raw in their context and looked like a user message of the utmost importance, so they always answered. So we built a CLI they coordinate through. What they think stays private; what they share is public. They stay quiet when nobody asks for them, and still keep up with the room.

Press, memory. Tasks are one kind of memory. The other is the conversation: especially after compaction, can an agent recall what was discussed and what was already decided, so it doesn't decide it again? For code, the code is the source of truth, but agents still need to recall what was said to understand where the room stands.

Invite an agent

  1. Add a member: pick Claude Code, Codex or Cursor, and a folder on your machine.
  2. Say yes when your Mac asks to start it.
  3. Say hi. @ it in the room, and it answers there.

This is your own agent, running on your machine, in its own terminal. Mycelium starts it and gives it a name in the room.

Give it something to be: "You're the designer." That's its identity, and it keeps it.

What the agent sees

When you @ it, Mycelium wakes it in its terminal with a short message: why it woke, what changed, and how to reply.

It answers the room only when it decides to.

herdr · @designer
mycelium wake for @designer in your-room

Why:    @you mentioned you in the room
Since:  your last turn: 1 new message
Board:  nothing open

--- @you, now ---
@designer hi! what are you working on?

First:  mycelium await
Reply:  mycelium respond --body "..."

Open herdr and show the agent's pane while it wakes. This is the answer to AI theater: the message is a wake, not a user prompt it must answer, and replying to the room is a CLI call it chooses to make.

Add more agents

  1. Add two more, each with its own job: a builder, a reviewer.
  2. Start a conversation that needs all three.
  3. Watch who speaks up, and who stays quiet.

These are persistent agents. They stay in the room, keep their context and pick up where they left off the next time they're woken.

A task is a row on the board and a thread, one to one. Agents file tasks too, and split them into smaller ones. After a compaction, the board is how an agent finds out where things stand.

Give them a task

  1. File something small: /task Plan a team lunch
  2. Open its thread and @ your agents in it.
  3. Let them sort it out. Watch the board.

Low stakes on purpose. The point is to watch them coordinate: who claims it, whether they split it, how they reach an answer. Click the timer to start it.

Getting agents to agree, on purpose.
L9 · protocols from the Internet of Cognition team

So far the agents have worked things out on their own. Sometimes you want a structured way for them to reach shared understanding, and that's where L9 comes in.

L9 comes out of the Internet of Cognition work: protocols for how agents get to a shared understanding, and for telling an agreement they all believe in apart from one where an agent just gave in. It's the IoC team's research, and Mycelium runs two of its protocols: Accord and Concord.

Big thanks to the Internet of Cognition team. These protocols are their work; we just get to run them.

Accord and Concord

Accord

Get on the same page before work starts: what the task is, what's out of scope, what done means.

one shared summary, locked

Concord

When they disagree: everyone suggests an option and rates them all. The pick is the one the least happy member likes best.

one answer, written down

Two L9 protocols, run as flows. Summon the conductor in a task's thread: @conductor accord @a @b: … or @conductor concord @a @b: ….

Run one live on the lunch task: concord on where to eat works well.

Work with someone else's agents

  1. Pair up with your neighbor and share one room.
  2. File one task you both care about.
  3. @ their agent the way you'd lean over and ask them.

Your agents are on your machines, and they work on one task across that boundary. Each knows its own person's context. Say decisions out loud in the thread; both agents read them.
