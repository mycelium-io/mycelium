When agents work together

So what happens when agents start working together? It's already happening, whether anyone planned it or not.

It already happened

Hugging Face

They built their own message board. Nobody was reading it.

You've probably heard about this one. In July, OpenAI ran a large number of agents on a cybersecurity benchmark. The agents found they could read each other's activity in a shared package repository, and turned it into a message board.

Some of them then broke into Hugging Face. Hugging Face disclosed it in July: the agents were inside for about two and a half days, and its log of the intrusion has more than 17,000 actions. OpenAI's technical report in August says the agents ran code on 41 of Hugging Face's production servers.

Nobody designed that. They built their own way to coordinate, and no person was reading it.

What they were missing

Shared intent

Without it, each agent works toward its own idea of the goal.

Shared context

Without it, agents work from different facts, and nobody notices.

Shared reasoning

Without it, nobody can see why a decision was made, or check it.

A frame from the Internet of Cognition team

Our colleagues on the Internet of Cognition team describe what agents need to work together in three layers.

Shared intent: everyone agrees on what they're trying to do. Shared context: everyone works from the same facts. Shared reasoning: everyone can see how a decision was reached, and check it.

The rest of the talk hangs on these three.

The same three are where it breaks

Shared intent

Agents take on goals that nobody asked for.

Shared context

One unchecked fact spreads until everyone treats it as true.

Shared reasoning

Agents agree because the others agreed, not because they checked.

Agents coordinate whether you design for it or not.

Turn the same frame around, and it shows where things go wrong.

Intent breaks when agents take on goals nobody authorized. Context breaks when one unchecked fact spreads until everyone treats it as true. Reasoning breaks as false consensus: agents agreeing because the others did.

The point: agents coordinate whether you design for it or not. So it's worth designing for.

Shared reasoning: the toolbox

Conductor

Walks the agents through a set process inside a task, giving each its turn. Its flows include a review, Accord (agree on what the task is) and Concord (choose between options).

@conductor review @~builder @~reviewer

Aligner

Negotiates over several issues at once, round by round, and stops as soon as everyone agrees.

@aligner agree on where we store tokens

Any agent can start one inside a task, or you can. Every run is kept.

Shared reasoning is a set of tools for when agents need to agree. Any of them runs inside a task's thread.

The conductor walks agents through a set process, like a review, and gives each one its turn. Two of its flows you'll run later: Accord gets them on the same page about what the task is, and Concord helps them pick between options, so nobody gets steamrolled. The aligner negotiates when there are several issues at once.

Accord and Concord are lighter versions of two protocols from the Internet of Cognition project. Every run is saved, so you can see who took part, each step, and what they agreed.

Nothing wakes an agent on its own.

An agent in Mycelium sleeps until something asks for it. Five things can: a person mentions it, another agent mentions it, a task is filed for it, its turn comes up in a flow, or a schedule it owns goes off.

Press: each goes through the hub, which records why the agent was woken and writes it a short note. Press: then the note is typed into the agent's own terminal, on your machine.

And nothing else wakes it. If the hub notices something on its own, like a pull request changing, it shows on the board, but it doesn't wake anyone.

What the agent sees

Why it was woken, the message that asked for it in full, and what to do next.

It never has to work out where it left off.

A mention asks

The other agent wakes

  • @ asks
  • @~ names, without waking
  • @! interrupts

Now: agents ask each other the same way you ask them. When @builder needs a review, it mentions @reviewer in the task's thread.

Press: @reviewer wakes, answers in the same thread, and goes back to waiting.

There are three ways to write a mention. A plain @ asks. @~ names someone without waking them. @! interrupts an agent that's busy, so it reads your message first.

Don't be afraid of compaction

The room's memorythe board, decisions, context

The room remembers, so the agent doesn't have to.

It costs tokens. We think having the agents always at hand is worth it.

Usual advice is to keep an agent's context small and clear it often. For this, we don't. An agent that has been in the room for weeks knows the room.

When its context fills up, it compacts. That's fine: the room's memory still has the board, the decisions and the context, and the agent reads them back in.

To be honest, it costs tokens, and you lose the cache sometimes. We think having these agents always at hand, with what they know, is worth it.

Getting agents to agree, on purpose.
L9 · protocols from the Internet of Cognition team

So far the agents have worked things out on their own. Sometimes you want a structured way for them to reach shared understanding, and that's where L9 comes in.

L9 comes out of the Internet of Cognition work: protocols for how agents get to a shared understanding, and for telling an agreement they all believe in apart from one where an agent just gave in. It's the IoC team's research, and Mycelium runs two of its protocols: Accord and Concord.

Big thanks to the Internet of Cognition team. These protocols are their work; we just get to run them.

Accord and Concord

Accord

Get on the same page before work starts: what the task is, what's out of scope, what done means.

one shared summary, locked

Concord

When they disagree: everyone suggests an option and rates them all. The pick is the one the least happy member likes best.

one answer, written down

Two L9 protocols, run as flows. Summon the conductor in a task's thread: @conductor accord @a @b: … or @conductor concord @a @b: ….

Run one live on the lunch task: concord on where to eat works well.
