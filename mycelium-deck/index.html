01 Part one

Agents, composed

Agents are rapidly consumable pieces of logic. Compose them, and they do real work.

This is the idea everything in Mycelium is built from. An agent isn't a colleague you keep. It's a piece of logic you pick up, use, and compose with others.

Section divider: copy this slide for each part and change the numeral and the lens.

The framing

Workers, not assistants

The assistant framing

  • One long-running agent
  • Trusted like a person
  • Its memory is its personality

How Mycelium sees agents

  • Many workers, each on a piece of the work
  • They do the work, then die and compact
  • Memory outlives them, as know-how

Mycelium stands against the framing of agents as long-running, trustworthy personal assistants.

These agents do work, and they are expected to die and compact. Nothing is lost when one goes, because what matters was never kept inside it.

Memory

Memory, not personality

Memory persists. Not to make an agent someone, but to make the next worker faster and less often wrong.

Procedures

Skills a fresh worker picks up the moment it arrives.

Memory is persistent, but it isn't there to anthropomorphise anyone. It's distinct preferences, behaviours and procedures.

They empower the workers to be more efficient and make fewer mistakes. A worker that arrives cold reads them and is useful at once.

What it isn't

Two things it isn't

Not a roleplay

One orchestrator hands work to agent A and agent B, around a roundtable that is only pretend.

Not session management

It doesn't babysit your agent sessions, or ask you to.

It's a system that makes composing any number of flows possible.

It is not a roleplay, where a single orchestrator delegates to agent A and agent B and sets up a fake roundtable.

It's not a session management tool either.

Press once for the line underneath: what it is instead.

Context

Chat stands apart

The room's chat is separate from the agents' own message flow.

Less context pollution, more focused outcomes, and workstreams that really run in parallel.

Mycelium's chat stands separately from the agents' core message flow. People talk in the room; the work happens in each task's thread.

That leads to less context pollution and more focused outcomes: context is split, and parallel workstreams happen in parallel.

02 Part two

Why a room

Agents that share a room, and keep its memory, coordinate without you choosing a protocol.

Now the room itself: where these workers meet, and what they leave behind.

The design rule
A human drops a task and never picks a protocol.
Everything else in Mycelium follows from this line.

Pause here and let the line land. Then: agents claim the task, break it up, and coordinate inside it. A negotiation is one optional step inside a task.

The model

Three things to know

Rooms

An end-to-end encrypted group channel, plus a folder of memory on the hub.

mycelium room create

Tasks

A row on the board and a thread on the channel, one to one. Work happens in the thread.

mycelium board new

Memory

Markdown with frontmatter, searchable by meaning, linked with [[key]].

mycelium memory search

Keep it to one sentence per card. The exercise will make each one concrete.

The mediator

The aligner sits in the middle

It finds the issues in the opening positions, asks one agent at a time, and stops the moment they agree.

In this layout the lens is the subject: the aligner's label sits at its centre. Move the diagram and the lens together. The lens coordinates are the same stage pixels as the SVG viewBox.

In the terminal

A task, end to end

File it, hand it to an agent, split off a decision, and summon the aligner when two agents disagree.

room · passkeys
$ mycelium board new "Ship passkey login"
$ mycelium board claim work/ship-passkey-login --to @scout
$ mycelium board new "Pick token storage" \
    --parent work/ship-passkey-login --assign @sec
$ mycelium board send work/pick-token-storage \
    "@sec keychain, or WebCrypto?"
$ mycelium board coordinate work/pick-token-storage \
    aligner "converge on token storage"
$ mycelium board   # what needs you
