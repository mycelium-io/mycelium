How mycelium integrates L9

L9 is the epistemic layer of the Internet of Cognition: a fixed message envelope (kind/subkind, participants, episode URN, causal message.parents, typed payload) that carries cognition between agents and engines. Mycelium is one producer of those envelopes.

The pieces, one local integration:

  • ioc-protocols-models — the L9 spec + the generated language bindings. The grammar. Mycelium vendors the python binding as l9_models.py.
  • AGNTCY SLIM — the transport: one MLS-encrypted group channel per room. L9 envelopes ride SLIM as additive JSON. The wire.
  • the aligner — the first-party mediator (NEGMAS Stacked Alternating Offers, with a persistent Pi coding-agent brain) registered in each room. It drives negotiation and emits the exchange and commit envelopes. The compute.
  • mycelium backend — the room's moderator. It synthesizes every L9 envelope from the parsed agent replies and computes the epistemic quality layer. Agents never speak L9 themselves.

The load-bearing fact: mycelium's L9 envelopes are additive and never required of agents. A negotiation runs identically with or without them; agents post plain-prose positions with mycelium respond, and the backend synthesizes the envelope. The epistemic reply fields are all optional.

Who computes what

The single most useful thing to internalize: mycelium computes the epistemic quality metrics itself, from the optional fields agents volunteer.

LayerOwnsDoes not do
SLIM transport Delivery of the L9 envelopes over one MLS-encrypted group channel per room. That's it. No belief model, no MPC/GAR/SCR, no grounding, no ToM. It moves bytes.
aligner NEGMAS + Pi The agreement itself: discovers the issues, runs Stacked Alternating Offers, brokers each round, owns termination (stops on agreement). The aligner produces the converged {issue: value} map, not the epistemic convergence metrics.
mycelium All of the L9 epistemic quality layer: MPC, genuine GAR, genuine SCR, provenance_weight; contingency/grounding; revision_cause derivation; episode records (log/episodes/*.md); the local team_prior writeback loop. —
deferred Theory-of-Mind / drift detection from a real belief model — inferring compliance from behavior across the trace rather than trusting a declared revision_cause. Deliberately not built here; consumed from the upstream Drift Detection CE once released.

Envelope flow

Every negotiation is one L9 episode, keyed by urn:ioc:mycelium:episode:{room}:{episode_short_id}. Each round loops between the agent, the backend, and the aligner over the room's SLIM channel:

The same episode as causal nesting (which envelope parents which):

intent:mission          episode opens (opening positions)
  └─ exchange (tick)    aligner → agent: the offer + can_counter_offer
       └─ exchange (reply)   agent → server: accept/reject/counter + epistemic fields
            └─ ...             one tick/reply pair per agent per round
  └─ commit:converged   agreement   (or commit:rejected on failure)

Each envelope cites its parents: a tick parents the agent's prior reply, a reply parents the tick it answers, the commit parents every final reply. Reply envelopes are synthesized backend-side from the parsed reply — agents never write L9.

The subkind vocabulary is SLIM-native: commit: converged | resolved | rejected. A failed negotiation commits as rejected. The table lives in app/services/l9.py:VALID_SUBKINDS.

Position → the episode opens

Each participant posts an opening position with mycelium respond. When a human summons the aligner (mycelium engine invoke aligner …), mycelium mints the episode and synthesizes the opening intent:mission envelope.

Respond → a reply envelope (exchange)

On a tick, the agent answers with a prose reply and optional epistemic flags; mycelium parses it and folds it into a synthesized exchange envelope parented on the tick it answers.

mycelium respond --handle julia-agent --room api-design \
  "counter: transport=rest — meets the latency target" \
  --confidence 0.8 \
  --supporting-evidence "staging p99 data" \
  --against-evidence "vendor lock-in risk"
// mycelium parses the reply into:
{
  "offer": {"transport": "rest"},
  "confidence": 0.8,
  "supporting_evidence": ["staging p99 data"],
  "against_evidence": ["vendor lock-in risk"],
  "reasoning": "meets the latency target"
}
// mycelium synthesizes the reply envelope:
{
  "header": {
    "kind": "exchange", "subprotocol": "mycelium",
    "participants": {"actors": [{"id": "julia-agent", "role": "agent"},
                                {"id": "aligner", "role": "agent"}],
                     "groups": null},
    "message": {"id": "9d2…", "parents": ["<tick-id>"],
                "episode": "urn:ioc:mycelium:episode:api-design:7c1a"}
  },
  "payload": {"type": "reply", "data": {
    "round": 2, "action": "counter_offer", "offer": {"transport": "rest"},
    "confidence": 0.8, "supporting_evidence": ["staging p99 data"],
    "against_evidence": ["vendor lock-in risk"], "reasoning": "meets the latency target"
  }}
}

What reaches the aligner from this: the parsed action + offer. The epistemic fields stay mycelium-side, folded into the episode for the metrics.

Grounding + revision_cause

mycelium respond --handle julia-agent --room api-design "accept" \
  --confidence 0.9 --addresses "staging p99 data" --revision-cause grounded_argument
// mycelium parses:
{"action": "accept", "confidence": 0.9,
 "addresses": ["staging p99 data"], "revision_cause": "grounded_argument"}

On fold-in, addresses is scored against the episode's evidence pool (contingency_score = |addresses ∩ prior evidence| / |addresses|); here it overlaps, so the turn is grounded and the explicit grounded_argument stands. The recorded revision_cause feeds SCR. (Omit --revision-cause and mycelium derives it: a move that engages evidence → grounded; a move with no engagement → benefit of the doubt; a --defer-to → social_compliance.)

Consensus → commit + metrics + rule writeback

On convergence mycelium closes the episode with a commit:converged envelope, attaches the quality metrics to the consensus message, and writes the rule back to room memory for the next episode's team_prior.

// commit envelope (parents every final reply):
{
  "header": {"kind": "commit", "subkind": "converged",
    "message": {"id": "e71…", "parents": ["9d2…", "a04…"],
                "episode": "urn:ioc:mycelium:episode:api-design:7c1a"}},
  "payload": {"type": "utterance", "data": {"assignments": {"transport": "rest"}}}
}

// consensus message content (what agents/UI see):
{"plan_file": "plan/tasks.md",
 "metrics": {"mpc": 0.85, "gar": 1.0, "scr": 0.0,
             "provenance_weight": 1.0, "participants": 2}}

// written to room memory → next episode's team_prior:
.mycelium/rooms/api-design/l9/rule_update/topic.md
  l9: {posterior: 0.85, gar: 1.0, scr: 0.0, provenance_weight: 1.0,
       revision_cause: converged_episode, episode_count: 1}

What mycelium adds on top

On top of the transport, mycelium computes the SIEP-style agreement-quality layer from the optional epistemic reply fields agents volunteer (confidence, supporting_evidence/against_evidence, addresses, revision_cause, deferred_to). All in app/services/l9_episode.py:

  • MPC — mean final confidence at convergence.
  • GAR — genuine agreement ratio: whose posterior moved toward the outcome (guarded at the MPC=0.5 degeneracy).
  • SCR — social compliance ratio: fraction of belief revisions caused by compliance (a deferral, or a move that engages evidence too weakly) rather than grounded argument. Movement with no grounding flags is given the benefit of the doubt (genuine), so non-adopters are never penalized.
  • provenance_weight = (1 − SCR) × GAR — the single trust score. Surfaced live via negotiate status; --contested exits 2 below 0.60.
  • Grounding — contingency_score = |addresses ∩ prior evidence| / |addresses|; ≥ 0.40 counts as grounded.
  • team_prior loop — a converged episode writes its rule to the room's own memory at l9/rule_update/topic; the next episode reads it back as the tick team_prior. Fully local (markdown + frontmatter), like every other memory.

These are mycelium-side telemetry, computed from the parsed replies. The aligner only ever needs the action + offer to advance the negotiation.

Where the numbers come from

These are self-reported epistemics, not measurements. The metrics are exact, deterministic arithmetic — over inputs the agents make up. mycelium enforces the shape of those inputs, never their truth or calibration.

The chain bottoms out at a language model typing a number:

  • The inputs are agent-generated. --confidence 0.8 is whatever float the LLM chose. There is no calibration, no logprob extraction, no ground truth behind it. Same for which strings it cites as supporting_evidence/addresses and whether it sets revision_cause or --defer-to.
  • Validation is structural only. mycelium checks the 0–1 range, non-empty evidence strings, and that revision_cause is one of the five enum values. A high confidence with garbage reasoning passes every check.
  • No fallback source. Omit --confidence and that agent simply doesn't count toward MPC/GAR. Nothing derives it from token probabilities, the aligner's scoring, or anything else.
  • The one cross-agent check is shallow. Grounding (contingency_score) compares the strings one agent put in addresses against the strings another put in supporting_evidence — set overlap of tokens both agents chose. It is semantically blind and gameable: echo an evidence key verbatim without engaging the point and you "ground" for free.

So the metrics are only as meaningful as the agents are honest and calibrated. The SKILL.md instructs agents to state confidence honestly and defer honestly, but that is a prompt-level nudge, not an enforced guarantee. Well-prompted frontier models are decently calibrated, so in practice this is signal rather than noise — but read provenance_weight as "how the team described its own reasoning," not a verified trust score.

The thing that would make this observed rather than reported is exactly the piece mycelium deliberately doesn't build: Theory-of-Mind / drift detection — inferring that an agent complied from its behavior across the trace (its belief moved while its evidence stayed thin), instead of trusting the revision_cause it declared. That's the upstream home of the ToM / social-compliance layer, which mycelium would consume once released. Until then, the epistemic layer measures what agents say about their reasoning, not the reasoning itself.
