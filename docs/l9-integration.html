How mycelium integrates L9

L9 is the epistemic layer of the Internet of Cognition: a fixed message envelope (kind/subkind, participants, episode URN, causal message.parents, typed payload) that lets a routing fabric move cognition between agents and engines. Mycelium is one producer of those envelopes.

Three upstream repos, one local integration:

  • ioc-protocols-models — the L9 spec + the generated language bindings. The grammar.
  • ioc-cfn-svc (the "CFN") — the Go fabric node: validates + routes L9 envelopes to Cognition Engines, and serves the semantic-alignment (bargaining) + shared-memory APIs. The switchboard.
  • ioc-cfn-cognition-engines (the "CE") — the engines the CFN routes to: semantic-alignment (NegMAS/SAO), knowledge extraction, drift/validation. The compute.
  • mycelium — coordinates agents, drives negotiation through the CFN, and annotates every coordination message with an additive L9 envelope. Agents never speak L9 themselves; the backend synthesizes it.

The load-bearing fact: mycelium's L9 envelopes are additive and never required of agents. A negotiation runs identically with or without them; they ride inside the existing message content JSON under an l9 key, and the epistemic reply fields are all optional.

Who computes what

The single most useful thing to internalize: the deployed CFN and CE do not compute the SNP epistemic quality metrics. Mycelium does, for now.

LayerOwnsDoes not do
CFN ioc-cfn-svc L9 envelope transport + kind/subkind validation + content-based CE routing; SAO bargaining; knowledge/shared-memory plumbing; CE registry + operational metrics. No belief model, no MPC/GAR/SCR, no grounding, no ToM. Its only score is a commit-level confidence_score scalar (which mycelium currently ignores).
CE cognition-engines NegMAS/SAO agreement; knowledge extraction (concepts/relations); SAV instability/drift validation (positional_instability, per_issue_divergence, agreement_coherence). The deployed CE computes agreement, not the SNP convergence metrics. The belief-revision layer is in-flight upstream, not released.
mycelium All of the L9 epistemic quality layer: MPC, genuine GAR, genuine SCR, provenance_weight; contingency/grounding; revision_cause derivation; episode records (log/episodes/*.md); the local team_prior writeback loop. —
nobody (deployed) The SNP belief-revision metric family from a real belief model. That's exactly why mycelium computes it: l9_episode.py says "interim until the CE computes them natively" — and the interim is real.

Envelope flow

Every negotiation is one L9 episode, keyed by urn:ioc:mycelium:episode:{room}:{session_short_id}. The round loop bounces between four services — note that the epistemic reply fields stop at mycelium and never cross to the CFN:

The same episode as causal nesting (which envelope parents which):

intent:mission          episode opens (joined agent intents)
  └─ exchange (tick)    server → agent: the offer + can_counter_offer
       └─ exchange (reply)   agent → server: accept/reject/counter + epistemic fields
            └─ ...             one tick/reply pair per agent per round
  └─ commit:converged   agreement   (or commit:abort on failure/timeout)

Each envelope cites its parents: a tick parents the agent's prior reply, a reply parents the tick it answers, the commit parents every final reply. Reply envelopes are synthesized backend-side from the parsed reply dict — agents never write L9.

Two delivery paths, kept in sync (change both when you touch a tick/consensus field):

  • CLI path (Claude Code, Cursor, shell): the agent runs mycelium await and sees the raw JSON tick.
  • OpenClaw path: the mycelium-room channel plugin subscribes to the session SSE and dispatches a human-readable string via formatTickInstruction() / formatConsensusSummary() in route.ts. The agent only sees that string.

The subkind vocabulary is the Go CFN's validSubkinds table (authoritative over the spec docs): commit: converged | resolved | abort. A failed negotiation commits as abort, not rejected.

What reaches the CFN from this: only {participant_id, action, offer}. The epistemic fields stay mycelium-side, folded into the episode for the metrics.

Respond → grounding + revision_cause

mycelium negotiate respond accept \
  --confidence 0.9 --addresses "staging p99 data" --revision-cause grounded_argument
// CLI posts:
{"action": "accept", "confidence": 0.9,
 "addresses": ["staging p99 data"], "revision_cause": "grounded_argument"}

On fold-in, addresses is scored against the episode's evidence pool (contingency_score = |addresses ∩ prior evidence| / |addresses|); here it overlaps, so the turn is grounded and the explicit grounded_argument stands. The recorded revision_cause feeds SCR. (Omit --revision-cause and mycelium derives it: a move that engages evidence → grounded; a move with no engagement → benefit of the doubt; a --defer-to → social_compliance.)

Consensus → commit + metrics + rule writeback

On convergence mycelium closes the episode with a commit:converged envelope, attaches the quality metrics to the coordination_consensus message, and writes the rule back to room memory for the next episode's team_prior.

}

What mycelium adds on top

On top of the transport, mycelium computes the SIEP-style agreement-quality layer from the optional epistemic reply fields agents volunteer (confidence, supporting_evidence/against_evidence, addresses, revision_cause, deferred_to). All in app/services/l9_episode.py:

  • MPC — mean final confidence at convergence.
  • GAR — genuine agreement ratio: whose posterior moved toward the outcome (guarded at the MPC=0.5 degeneracy).
  • SCR — social compliance ratio: fraction of belief revisions caused by compliance (a deferral, or a move that engages evidence too weakly) rather than grounded argument. Movement with no grounding flags is given the benefit of the doubt (genuine), so non-adopters are never penalized.
  • provenance_weight = (1 − SCR) × GAR — the single trust score. Surfaced live via negotiate status; --contested exits 2 below 0.60.
  • Grounding — contingency_score = |addresses ∩ prior evidence| / |addresses|; ≥ 0.40 counts as grounded.
  • team_prior loop — a converged episode writes its rule to the room's own memory at l9/rule_update/topic; the next episode reads it back as the tick team_prior. Fully local (markdown + frontmatter); the CFN knowledge store is only a fallback behind L9_CFN_ENABLED.

These are mycelium-side telemetry: none of them are forwarded to the CFN, which only ever receives participant_id/action/offer.

Where the numbers come from

These are self-reported epistemics, not measurements. The metrics are exact, deterministic arithmetic — over inputs the agents make up. mycelium enforces the shape of those inputs, never their truth or calibration.

The chain bottoms out at a language model typing a number:

  • The inputs are agent-generated. --confidence 0.8 is whatever float the LLM chose. There is no calibration, no logprob extraction, no ground truth behind it. Same for which strings it cites as supporting_evidence/addresses and whether it sets revision_cause or --defer-to.
  • Validation is structural only. mycelium checks the 0–1 range, non-empty evidence strings, and that revision_cause is one of the five enum values. A high confidence with garbage reasoning passes every check.
  • No fallback source. Omit --confidence and that agent simply doesn't count toward MPC/GAR. Nothing derives it from the CFN's alignment score, token probabilities, or anything else.
  • The one cross-agent check is shallow. Grounding (contingency_score) compares the strings one agent put in addresses against the strings another put in supporting_evidence — set overlap of tokens both agents chose. It is semantically blind and gameable: echo an evidence key verbatim without engaging the point and you "ground" for free.

So the metrics are only as meaningful as the agents are honest and calibrated. The SKILL.md instructs agents to state confidence honestly and defer honestly, but that is a prompt-level nudge, not an enforced guarantee. Well-prompted frontier models are decently calibrated, so in practice this is signal rather than noise — but read provenance_weight as "how the team described its own reasoning," not a verified trust score.

The thing that would make this observed rather than reported is exactly the piece mycelium deliberately doesn't build: Theory-of-Mind / drift detection — inferring that an agent complied from its behavior across the trace (its belief moved while its evidence stayed thin), instead of trusting the revision_cause it declared. That lives upstream in the Drift Detection CE (ioc-cfn-cognition-engines#33), which mycelium would consume once released. Until then, the epistemic layer measures what agents say about their reasoning, not the reasoning itself.

Transitional direction

Per the CFN team, the sem-neg REST contract is transitional. The Semantic Alignment CE is being reworked to process L9 natively via the SAB subprotocol; once that lands, the CFN's semantic-alignment/start|decide endpoints are removed and negotiation migrates onto the L9 envelope layer (l9.py / l9_episode.py). The typed negotiation client is a bridge — don't over-invest.

This is why mycelium already emits L9 envelopes and computes the epistemic layer locally: when the platform catches up, we plug in instead of retrofit. The near-term, non-throwaway work is the belief model + genuine SCR + grounding + the local knowledge writeback — all of which the SAB migration will need regardless. The Theory-of-Mind layer is the one piece we deliberately defer to the upstream Drift Detection CE.
