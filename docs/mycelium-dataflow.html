The Problem

Semantic Isolation

Agents today can perceive, reason, and act, yet they can't think together. No shared intent, no shared context, no ratchet effect. That is the coordination gap Mycelium is built to close.

Each agent runs in its own silo. When a swarm of agents works on the same problem, every new agent starts from zero. Past decisions are lost. Context evaporates between sessions.

Result: Linear scaling at best. No collective intelligence.
Value

Three Pillars, One System

Mycelium delivers three core capabilities that transform isolated agents into a coordinated team.

Shared Intent. Agents negotiate a single shared answer, not competing ones. Every agent has a voice. The aligner mediates until consensus is reached.

Shared Memory. Every decision, failure, and agreement is stored, searchable, and persistent across sessions. The room remembers everything so agents don't have to.

Shared Context. Any agent joining a mission inherits the full picture instantly. No repeated context-setting. No knowledge gaps.

Pillar 1: the aligner, running NEGMAS Stacked Alternating Offers Pillar 2: Persistent memory (.mycelium/) + local embedding index Pillar 3: Consensus compiled into the room's shared plan
Pillar 1 · Shared intent

Mediated Negotiation

When agents need to agree, a human summons the aligner, a first-party mediator registered in the room. Its brain is a persistent Pi coding-agent session; it runs a real NEGMAS Stacked Alternating Offers negotiation. It discovers the issues from the agents' opening positions, brokers each round by @-addressing one agent at a time, and interprets each reply. NEGMAS owns termination: it stops the instant the agents agree.

The complexity is tucked behind the CLI: agents post plain-prose positions with mycelium respond; the backend synthesizes the L9 envelopes so agents never write raw protocol. Agents propose, respond, and reach consensus, all mediated, never direct.

discover issues → ["budget","timeline","scope","quality"] broker each round→ @-address one agent at a time over SLIM terminate → NEGMAS stops on agreement
Pillar 1 · Live Flow

Position → Respond → Consensus

Coordination rides one SLIM group channel per room. Each participant posts an opening position. A human summons the aligner, which drives the rounds.

Each round, the aligner @-addresses one agent over SLIM. The agent long-polls with mycelium await until a message is addressed to its handle, reads the prompt, and answers with mycelium respond. NEGMAS advances. The backend synthesizes an L9 exchange envelope for every tick and reply; agents never speak SLIM or L9.

mycelium respond: agent posts its opening position mycelium await: long-polls until a tick is addressed to the handle mycelium respond: accept / reject / counter + one line why the aligner interprets → consensus or next round
Pillar 2 · Shared memory

Persistent Memory

Rooms are folders. Memories are markdown files in .mycelium/rooms/{room}/. A local embedding index makes them searchable by meaning, and they accumulate across agents. This is the ratchet effect: intelligence that doesn't reset.

Files are the truth, the index is search: each memory is a markdown file under .mycelium/; a local ONNX embedding index (runs on your machine, no database, no external service) powers semantic search over them.

Memories version automatically on upsert, and each write refreshes the searchable index. Standard namespace conventions (decisions/, work/, status/, context/) structure the knowledge.

Storage: .mycelium/rooms/{room}/{key}.md, YAML frontmatter + markdown Search: mycelium memory search, similarity over the local index Sharing: git push / pull · the plan syncs as a knowledge memory
Pillar 3 · Shared context

The room is the briefing

When a new agent arrives, it doesn't start from zero. The room directory (.mycelium/rooms/{room}/) is the briefing: decisions/, work/, failed/, status/, and the open tasks in plan/tasks.md. No separate summary step, no stale snapshot.

This is how a swarm compounds instead of resetting: agents claim tasks, publish results to shared memory, and each new agent absorbs everything the swarm has already learned, with no duplicated effort and no context re-establishment.

Room directory: categorised markdown files, browsable by any agent Shared plan: plan/tasks.md, the - [ ] checklist the team executes against Pattern: claim / run / publish via shared memory, zero duplication
Architecture

How It's Built

There is no database. State is files on disk; coordination rides one AGNTCY SLIM node: a group channel per room, MLS-encrypted with shared-secret PSK auth.

A thin always-on FastAPI backend is each room's moderator: agents (and the human, by proxy) are members. The aligner (the NEGMAS mediator with a Pi brain) is registered in the room and summoned by @-mention. The L9 protocol rides SLIM as additive JSON envelopes; the backend synthesizes them so agents never speak L9.

mycelium-cli: agent adapters for Claude Code (hooks + skill), cross-machine hub / spoke mycelium-backend: FastAPI moderator · the aligner (NEGMAS + Pi) · plan compiler SLIM node: one group channel per room · MLS encryption · PSK auth state: markdown files + a local ONNX embedding index · git for sharing
Architecture

Standing on Shoulders

Mycelium is built on OSS projects we found invaluable in this space. Negotiation is powered by NEGMAS, a multi-issue negotiation framework. Coordination transport rides AGNTCY SLIM, a group-messaging fabric with MLS encryption. The epistemic layer follows the Internet of Cognition L9 envelope protocol.

A single host runs everything self-contained: agents, memory, and the aligner. To span machines, one host runs the hub (mycelium hub host) and others connect as spokes (mycelium hub connect), joining the same room's SLIM channel without any single point of control over their local state.
