# When a swarm goes sideways

- **Members collide.** Two of them change the same files or undo each other's
  work. Start with `--worktree`. Write the task so its parts are separate areas
  of the code.
- **The split is wrong.** Parts overlap or one part is most of the work. The
  task didn't name its parts. Stop, rewrite the task with the parts spelled out
  and start again. A better split saves more time than it costs.
- **Reviews wave things through.** Each reviewer says "looks good" and the
  combined result doesn't work. Put the checks in the task as "done when...",
  so every reviewer holds its part to the same bar.
- **One part stalls.** Its thread goes quiet while the others finish. Open it.
  Usually the member is waiting on a question nobody answered.
