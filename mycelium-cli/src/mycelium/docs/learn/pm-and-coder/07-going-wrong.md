# When it goes wrong

Three things go wrong, and each has a tell in the thread.

- **The loop doesn't finish.** Review after review, nothing passes. The checks
  are vague, so nothing can meet them. Tighten them: each check should be
  something anyone could verify.
- **The PM approves everything.** Reviews say "looks good" without saying
  why. The brief needs to ask for evidence: a test that runs, a screenshot,
  the command's output.
- **The coder drifts.** It's busy with something the checks don't mention.
  Point the PM back at its own list, and ask it to hold the coder to it.
