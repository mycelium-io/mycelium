# Two kinds of stuck

This course is optional. Most tasks never need it: one agent takes the task,
asks when it's unsure, and the thread settles the rest. Reach for these two
flows when a team is stuck in one of two specific ways. Both run on the
conductor, inside the task's thread, and both save what they settle to the
room's memory.

**They don't share a picture of the task.** Each member is sure it knows what
the task is, and they don't agree. A request gets read as something broader
than was meant. One word means two things: "rename" as the label people see,
or as the name the code uses everywhere. The work collides, and nobody notices
until two pieces of it don't fit.

That's when to run **accord**. Everyone says what they understand the task to
be, and the points are merged into one shared summary, with anything that
doesn't line up flagged. Run it when a task changes hands, or before several
agents start on the same one.

**There are real options, and someone would otherwise just pick.** There are
two or three reasonable answers, and each has a cost someone will feel. Without
a flow, the first agent to act picks one. Three possible fixes get tried one
after another, or a behavior is chosen alone and its cost shows up a week
later, for someone who wasn't asked.

That's when to run **concord**. Everyone suggests an option and rates all of
them, and the answer is the one the least happy member can best live with. It
matters most when no one person can just decide: the agents belong to
different people, or nobody is around to break the tie.

The order is natural: accord before the work, so everyone agrees on the
problem; concord during it, when there's a real choice to make. If you can't
tell which one you need, ask whether the members disagree about **what** the
task is or about **how** to do it. "What" is accord. "How" is concord.
